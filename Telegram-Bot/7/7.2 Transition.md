# Translation: Getting Message Data and Filters (aiogram)

## Introduction

Let's consider a **handler** that triggers when the message "Information" is sent to a dialog with the bot:

```python
@router.message(F.text == "Information")
async def get_info(message):
    await message.answer("You can find all the necessary information on our website")
```

In the decorator arguments, a **filter** is used to search for messages with the required text. Let's figure out how it works. It turns out that `F` is an argument of the function that processes this action; in this case, `F` is the same as the `message` object. Therefore, `F.text` is the result of executing the `message.text` command. By analogy, you can write many different **filters** that sort written messages by their content, type, sender, and much more. To do this, let's study what parameters a message actually has.

---

## Getting Message Data

### Methods for Messages:
1. `message.from_user.id` – get the user's unique ID
2. `message.from_user.username` – get the user's username (starts with "@")
3. `message.from_user.first_name` – get the user's first name
4. `message.from_user.last_name` – get the user's last name (if provided in Telegram)
5. `message.text` – allows you to get the message text
6. `message.message_id` – allows you to get the message ID
7. `message.content_type` – allows you to get the type of the sent message (text, photo, document, etc.)
8. `message.caption` – allows you to get the caption for media messages (photos, videos, etc.)
9. `message.html_text` – get text with original formatting (more details in Chapter No. 11)

### Methods for Button Presses (Callbacks):
1. `call.data` – data of the pressed button
2. `call.message` – the message to which the button is attached
3. `call.from_user.id` – unique user ID
4. Other methods for getting user information, similar to message methods

> ⚠️ **Important**: Do not confuse `call.from_user` and `call.message.from_user`. Always use only the first one, since `call.message` is a message sent by the bot, not the user. Therefore, the method `call.message.from_user` will return data about the bot itself, which we don't need.

## Creating Your Own Filter

Using the methods from the previous section, you can create a filter with your required condition. For example, let's create a **handler** that will activate only for users who are in the administrators list. We'll write a class that inherits from the base aiogram filter class `BaseFilter`. In the `__call__` function, we'll write a check to see if the user's ID is in the administrators list.

```python
from aiogram.filters import BaseFilter

admins = [1046276866, 1234567890]

class FilterAdmin(BaseFilter):
    def __init__(self):
        pass
    
    async def __call__(self, message):
        return message.from_user.id in admins
```

Now let's write the main **handler**. Our filter will be in the decorator arguments:

```python
@router.message(FilterAdmin())
async def secret(message):
    await message.answer("This is not available to everyone")
```

If the user's ID is in the list of administrator IDs, the **handler** will activate regardless of what the user writes; otherwise, this **handler** will be ignored.

---

## Combining Filters

Several filters can be combined with each other:

```python
@router.message(FilterAdmin() and F.text == 'admin')
async def secret(message):
    await message.answer("This is not available to everyone")
```

In this example, the message will be sent to the user only if they are an administrator **and** type the word `"admin"` in the chat.

---

## Router Filter

Suppose we have a whole **block of handlers** that should all be checked for administrator status. In this case, it is more reasonable to set a common filter directly on the **router** to avoid writing it multiple times:

```python
router = Router()
router.message.filter(FilterAdmin())

@router.message(F.text == 'admin')
async def secret(message):
    await message.answer("This is not available to everyone")

@router.message(F.text == "secret")
async def secret_too(message):
    await message.answer("This is also not available to everyone")
```

Now all message **handlers** attached to this **router** will not allow unauthorized users.

> 💡 **Key Takeaway**: In aiogram, `F` is a magic filter object that allows concise syntax for matching message attributes. Custom filters inherit from `BaseFilter` and implement `__call__` to define matching logic. Filters can be applied to individual handlers or globally to a router for reusable access control.
