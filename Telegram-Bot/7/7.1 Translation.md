**Introduction**
Let's move on to the core aspect of developing any project: proper organization. To achieve this, all handlers should be placed in the `handlers` folder. In this lesson, we will learn how to correctly structure a project to ensure ease of use and code maintainability.

Project organization plays a key role, especially if your Telegram bot is expected to grow and become more complex. By properly dividing the code into logical blocks, you can avoid numerous issues related to maintenance, feature expansion, and debugging. It's important to remember that good code is not just code that works, but code that is easy to read and maintain.

Let's look at an **incorrect** example.
Suppose we move all handlers into a `main_menu.py` file located in the `handlers` directory. Additionally, we would need to import every module used when writing those handlers into this file. Besides keyboards and text constants, we would also have to import the `dp` (Dispatcher) object, which is the core component of the decorators that power a Telegram bot, for example: `@dp.message()`. Since this object resides in `main.py`, we would add the following line at the top of `main_menu.py`:


To solve this problem without resorting to workarounds and while preserving fundamental coding principles, we will use a built-in `aiogram` feature: **routers**.

**Moving to the Solution**
Let's assume we have several files containing handlers. Here is an example of how to structure one of them. We create a router object, which acts as a dispatcher analog, allowing us to bind handlers to it for processing user interactions.
```python
from aiogram import Router
router = Router()
```
The syntax for binding handlers remains identical to the dispatcher's syntax.
```python
@router.message()
async def start(message):
    await message.answer("Hello!")
```
You can create multiple handlers like this:
```python
@router.message(F.text == 'Antilya')
async def antilya(message):
    await message.answer("...The best")

@router.message(F.text == 'Aiogram')
async def aiogram(message):
    await message.answer("...Loves forever")
```
Next, we import and register these routers in `main.py` inside the `main` function, right before launching the bot:
```python
from handlers import example1, example2

async def main():
    dp.include_routers(example1.router, example2.router)
    await dp.start_polling(bot)
```
Here, `example1` and `example2` are example filenames containing handlers; you can register as many as needed.

**Conclusion**
Thus, we have learned how to split our project into logically independent files, making the code more structured and easily maintainable. This approach significantly simplifies adding new features and minimizes the risk of errors related to circular imports and other issues common in poorly organized code.
In the long run, this will save you considerable time and frustration during both development and project maintenance.
