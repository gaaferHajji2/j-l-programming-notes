#### Logging

Logging is an integral part of any serious project. With its help, you can track the program's behavior during execution, diagnose errors, and monitor the current state of the application. This is especially useful when developing Telegram bots.

In the case of a bot, logging allows you to record user actions — for example, button presses or text input — albeit without specific data about the actions themselves. You will be able to see whether the bot was launched, whether it received requests from users, and whether it managed to process them. This helps to find problem areas faster and track the bot's operation in real time.

Let's implement logging in the `main.py` file. To do this, import the standard `logging` library and configure it before initializing the bot and dispatcher objects. All key events during the bot's operation will be automatically recorded to the console or a file — depending on the settings.

```python
import logging

logging.basicConfig(level=logging.INFO)
```

After launching the bot, the first log lines will appear in the console, one of which will indicate your bot's name. This confirms that the bot is successfully initialized and ready to work.

When users start interacting with the bot — pressing buttons, sending messages, and performing other actions — new lines will begin to appear in the console. Each such line will display the result of event processing: if the bot successfully reacted to an action, a message marked "is handled" will appear. If the action was not processed by any of the handlers, you will see a log with the inscription "not is handled". This will help you track how the bot reacts to different scenarios and identify unhandled cases.

```text

INFO:aiogram.dispatch:Run polling for bot

```

#### Using a File

If you don't want the bot's console to be cluttered with unnecessary information, logging can be directed to a file.

```python
import logging

logging.basicConfig(level=logging.INFO, filename="logs.log", filemode="a")
```

- **filename** – a parameter that specifies the file handler object. Here you can specify the name and path to the file where logging should be performed.
- **filemode** – an optional parameter indicating the mode for working with the log file specified by the filename parameter. By default, the `filemode` parameter is set to `a` (append), meaning that records from all program sessions will be added to the file.

We have set up basic logging. Now, to find out what problems occurred in the bot, we just need to open the file and look at the logs. But almost always, to understand an error, we need to know the time it occurred. So let's add a timestamp.

```python
import logging

logging.basicConfig(level=logging.INFO, filename="logs.log", filemode="a",
                    format="%(asctime)s %(levelname)s %(message)s")
```

Thanks to the `format` parameter configuration, timestamps are added to the records, presented in a human-readable form.

There are many other log record attributes that can be used to customize the appearance of messages in the log file. You can learn about other attributes by visiting the official `logging` documentation via the link.
