## Why split a project into files?

Splitting a project into files allows you to:

• Simplify searching for a specific line or code element.
• Structure the code so that functions are written in one file, databases in another, and the user interface in a third.
• Make the code more readable for both you and other programmers.
• Simplify project maintenance and expansion, as changes in one file do not affect other parts of the code.
• Improve teamwork: different developers can work simultaneously on different project files.
• Increase code reusability, since modules organized in separate files can be easily imported into other projects.
• Spend more time writing the program.

* Naturally, if we are talking about writing a short program of 20 lines.

## Proper file naming

Let's start creating files where our bot's code will be stored. There are commonly accepted names for folders and files that are most convenient to use. We will show you the structure we use ourselves.

## Structure description

**main.py** — the main project file from which the bot starts. Here, all modules are initialized, and handlers are registered. Later, this file will contain the handlers we create in chapters five and six.

**handlers.py** — the main module that will contain the bot's logic. It will include all message and command handlers, designed as functions with the necessary filter-decorators.

**config.py** — a file containing all the main settings: bot token, database connection parameters, and other configuration data. Although storing such parameters directly in the code is not considered the most secure practice, it is the simplest and most convenient way when settings change infrequently. In more complex projects, it's preferable to use environment variables or separate configuration files (e.g., .ini or .json), and use config.py as a wrapper, but here we choose the most straightforward approach.

**Page 3**

**database.py** — a module responsible for database operations. This file will contain all the functions necessary for connecting to and interacting with the database. It separates data storage logic from the main part of the code.

**texts.py** — here, all bot text messages are collected: greetings, error notifications, and other templates. Although it's more convenient to store such texts outside the code — for example, in a database or separate files — in our case, the texts will be directly in the Python file since they usually don't change often.

**utils.py** — helper functions. This will contain methods for sending mass messages, working with external APIs (e.g., image or text generation), and other useful utilities.

**keyboards.py** — this module contains all the keyboards used by the bot: both static and dynamically created using functions.

**files** — a directory for storing media files: images, videos, and other files used by the bot.

**requirements.txt** — this is a special text file that lists all external libraries and dependencies necessary for your Python project (in this case, a Telegram bot). This file is used to install the required packages using the pip package manager.

## Why is requirements.txt needed?

• Allows other developers or servers to deploy the project with exactly the same libraries as you have.
• Simplifies dependency installation with a single command.
• Ensures project compatibility by fixing library versions.

## What does the file look like?

A simple example of content:

aiogram==3.3.0
python-dotenv==1.0.1
asyncpg==0.29.0

Each line is a library name and its version (it's recommended to specify the exact version to avoid compatibility issues).

## How to create requirements.txt?

If you already have a project with the necessary libraries installed, you can automatically generate requirements.txt with the command:

pip freeze > requirements.txt

## How to install dependencies from the file?

On any computer where you want to deploy the bot, simply run:

pip install -r requirements.txt

## What if the project is large?

Let's imagine a situation. We are writing a bot with a huge amount of functionality and before that we created a keyboards.py file where we write all our keyboards. The file will be huge and the main idea of splitting the project into files will be violated — "Simplify searching for a specific line or code element". Therefore, immediately after creating the project, we create the following folders instead of files:

• handlers
• keyboards
• texts
• utils
• files
• database

The main.py and config.py files always remain simply inside the project.

## ! Important to remember!

## Rules for naming files:

• File and folder names are written in lowercase.
• Uppercase letters should not be used at all.
• If the name contains 2 or more words, they are separated by underscores "_".

## Working with folders

Let's look at folder configuration. Take handlers as an example. Create an __init__.py file in it, in which we create a variable __all__, which will contain a list of strings: each string is the name of a Python file located in this folder. This way we import all files from this folder.

For example, for this folder we get the following code for the __init__.py file:

**Page 7**

__all__ = ['admin_panel', 'oferta', 'payment', 'products_menu', 'referal', 'start']
from . import *

The remaining folders are configured similarly.
