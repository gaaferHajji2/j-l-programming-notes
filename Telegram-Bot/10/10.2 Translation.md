### **Translation: Example of Using FSM**

**Creating a Calculator in a Telegram Bot using Aiogram and FSM**

In this lesson, we will learn how to create an interactive Telegram bot that functions as a calculator.

**General Principle**
The bot starts → the user presses `/start` → a keyboard appears → the user presses buttons → the expression accumulates → upon pressing `=`, the bot calculates the result.

FSM (Finite State Machine) allows us to **store the expression** entered by the user and know **what stage they are at**.

**Project Structure**
```text
calculator_bot_fsm/
├── config.py
├── handlers.py
├── keyboards.py
├── main.py
└── states.py
```

Below, we provide the complete code for this bot, file by file.

**states.py**
Moving states to a separate file is good practice, especially if there are many of them. This allows you to freely use them in various handler files, not just where they were created.

```python
from aiogram.fsm.state import StatesGroup, State

class CalcState(StatesGroup):
    waiting_for_input = State()
```

**config.py**
```python
token = "YOUR_TOKEN"
```

**main.py**
```python
import asyncio
from aiogram import Bot, Dispatcher
from aiogram.fsm.storage.memory import MemoryStorage
from config import token
from handlers import router

bot = Bot(token=token)
dp = Dispatcher(storage=MemoryStorage())

async def main():
    dp.include_router(router)
    await dp.start_polling(bot)

if __name__ == "__main__":
    asyncio.run(main())
```

**keyboards.py**
```python
from aiogram.types import InlineKeyboardMarkup, InlineKeyboardButton

def get_calc_keyboard():
    buttons = [
        ["7", "8", "9", "/"],
        ["4", "5", "6", "*"],
        ["1", "2", "3", "-"],
        ["0", ".", "=", "+"],
        ["C"]
    ]
    return InlineKeyboardMarkup(
        inline_keyboard=[
            [InlineKeyboardButton(text=btn, callback_data=btn) for btn in row]
            for row in buttons
        ]
    )
```

**handlers.py**
```python
from aiogram import Router, F
from states import CalcState
from keyboards import get_calc_keyboard

router = Router()

@router.message(F.text == "/start")
async def start_handler(message, state):
    await state.set_state(CalcState.waiting_for_input)
    await state.update_data(expression="")
    await message.answer("Enter expression:", reply_markup=get_calc_keyboard())

@router.callback_query(CalcState.waiting_for_input, F.data)
async def calc_handler(call, state):
    data = call.data
    current_data = await state.get_data()
    expr = current_data.get("expression", "")
    
    if data == "C":
        expr = ""
        await state.update_data(expression=expr)
        text = "Cleared"
    elif data == "=":
        try:
            result = eval(expr)
            text = f"{expr} = {result}"
            expr = str(result)
        except:
            text = "Error"
            expr = ""
        await state.update_data(expression=expr)
    else:
        expr += data
        await state.update_data(expression=expr)
        text = expr
        
    await call.message.edit_text(text, reply_markup=get_calc_keyboard())
    await call.answer()
```

**What FSM does in this calculator:**
1.  The `waiting_for_input` **state** defines that the bot is waiting for user input.
2.  Via `FSMContext`, the entered **expression** (`expression`) is stored separately for each user.
3.  This allows for future possibilities:
    3.a. Adding **states** for different stages (e.g., confirmation, history).
    3.b. Integrating the calculator into more complex **scenarios**.
