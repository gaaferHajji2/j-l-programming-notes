## Translation: FSM Integration

### Introduction

**States** are a powerful and complex tool in the **Aiogram** library. With their help, you can capture various text inputs and save them.

Let's provide an example. Suppose you need to create a bot with delivery functionality. After selecting a product, the user will need to enter their address. How do you ensure that after the user enters their address, a specific **handler** is executed?

This is where **FSM (Finite State Machine)** comes to help. This model helps move through specific functions according to a script, as well as save data for a particular user who has an active **FSM** state.

Simply put, we can create a **dialogue system** between the bot and the user. The general interaction scheme will be as follows: the bot asks a question, activates a state (**beginning of dialogue**), and the person enters text from the keyboard or selects an answer option from a button (**response to the bot**). Then the bot asks a new clarifying question, and so on. At the end, we **close the state**, and the user can use the regular functionality: selecting buttons from the menu and the like.

### Memory Configuration

When initializing the dispatcher in the **main.py** file, specify the storage:

```python
dp = Dispatcher(storage=MemoryStorage())
```

This line **creates a dispatcher with enabled memory** for storing FSM data—that is, it **enables support for the finite state machine (FSM)**.

### Working with States

Import the necessary modules and classes: the state class and the state group class.

```python
from aiogram.fsm.state import StatesGroup, State
```

Create a class that will inherit from the **StatesGroup** class. Inside it, create a set of fields—**states** using **State**.

```python
class DialogBot(StatesGroup):
    step1 = State()
    step2 = State()
    step3 = State()
```

Naturally, the class name and field names can be absolutely anything.

### Starting a Dialogue Between User and Bot

To activate a state in a **handler**, after which you expect user action, write the following:

```python
@router.message()
async def handler_step1(message, state):
    """
        Request the user to send a response
    """
    await state.set_state(DialogBot.step1)
```

Additionally, the function has another argument—**state** (you can name it differently). It is needed for working with the state machine.

In the second and third steps of the chain, specify calls to **step2** and **step3** respectively instead of **step1**.

### Identifying the Next Handler

Suppose the user sends some text to the bot after activating a state. How does the **handler** know that it should be activated next? Very simple: specify this state as a filter for the **handler**.

```python
@router.message(DialogBot.step1)
async def handler_step2(message, state):
   """
       Some processing of received data and response to the user
   """
   await state.set_state(DialogBot.step2)
```

### Ending the Dialogue

To complete the dialogue, you need to close the state. This must be done in the last link of our chain—after receiving the last required response from the user.

```python
@router.message(DialogBot.step3)
async def handler_step4(message, state):
   """
       Some processing of received data and response to the user
   """
   await state.clear()
```

### Processing Information

To get the text that the user sends, you can use the standard method: **message.text**

To save this data and use it in subsequent links of the chain, use the following method:

```python
await state.update_data(name=text)
```

Here, **text** is the variable we want to save, and **name** is its name in the memory storage. This storage is allocated by the computer on which the bot is located, using RAM. This means that when the bot restarts, all information is cleared and the dialogue will be interrupted. Thus, we obtain a temporary database that is convenient to use.

### Retrieving Data

If we need to get data that was loaded into the state machine storage, we apply this method:

```python
data = await state.get_data()
text = data['name']
```

We receive a dictionary **data** with all uploaded variables (not necessarily textual). From it, we extract our variable **text**. The dictionary key **name** is the name we specified when adding the variable to the storage.

Data can also be retrieved without using a dictionary:

```python
name = data.get("username", "Not specified")
```
